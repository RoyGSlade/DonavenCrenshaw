## Build: Phase 1, all working on a phone (Galaxy S26, finger + optional stylus)
Layout:
- full-bleed canvas; a bottom tool dock; a contextual sub-toolbar for the active tool ("the tools need tools")
- two-finger pan and zoom, pinch-zoom, palm rejection (ignore extra touches while drawing), haptic ticks via `navigator.vibrate`
- undo/redo with a deep stack, autosave of drafts to the server
- midnight look (black metal, cyan = active, pink = needs attention), text 16px or larger, targets 44px or larger
- plain HTML/CSS/JS, no outside scripts or fonts

1. **The lane populates as you draw.** The finger stroke is the centre line.
   - Smooth it live (Chaikin/Catmull-Rom plus RDP simplification) and render the real lane at the chosen width as you draw, in the chosen skin.
   - Auto-close the loop near the start, warn on self-overlap, and enforce the game's minimum width live.
   - Overlaps and too-tight turns get a pink marker right on the canvas while drawing.
2. **Skin picker** per track: Midnight metal / Classic, extensible.
   - The preview should use the game's real skin code. Fetch the skin branch: `git fetch ~/Desktop/DonavenCrenshaw-skin claude/stardust-track-skin`, merge it into this branch, then import `projects/Space-Shooter/gfx/trackSkin.js` for the studio preview.
   - Add an optional per-track `skin` field that the game's skin module honours (visual only).
3. **Width tools.**
   - A global width slider.
   - A **width brush:** paint over a stretch to set it wider or narrower.
   - **Auto taper:** smooth transitions between widths over a configurable length, so very wide can flow into narrow ("auto connect").
   - Show the width profile as a mini graph.
4. **Colour pens with meaning** (layers), each with its own sub-tools:
   - **Lane:** white
   - **Obstacles:** pink. A stroke becomes a row of obstacles along it, with spacing, type and size in the sub-toolbar.
   - **Landmarks:** violet.
   - **Shards:** cyan. A shard brush lays shards along the stroke with spacing; there's also a racing-line suggestion and a live shard count against the week's requirement.
   - **Hazard zones:** orange. Paint an area.
   - **Notes/decor:** grey. Free scribbles for intent; agents read them.
   - A layer panel: show, hide and lock; a per-layer eraser.
5. **Stamp / shape tools.** Pick a type (landmark, star, mine, sentry, barricade, gate/checkpoint, shard cluster, start/finish, or a custom requested item) and tap to place it.
   - Handles to scale, rotate and move. Long-press opens a properties sheet: size, rotation, behaviour (static / moving on a path / rotating / falling / timed), timing, layer.
   - A selection tool: tap or lasso, then move, duplicate, delete or align.
   - Snap to lane edge, centre line or grid. Mirror tool.
6. **"Request something new" modal card.** Fields:
   - Title, Description, Effect (what it does to the player)
   - Need / why
   - Type (obstacle / landmark / pickup / hazard / mechanic / decor / skin / other)
   - Behaviour type (static / moving / rotating / falling / timed / triggered)
   - Form (size, shape, look)
   - an attached sketch from the canvas region or a quick sketch pad, plus an optional photo

   On save:
   - Create a board card through the server's existing LHC integration (the `--lhc` CLI). Find whether the CLI can attach images; LHCmemoryS main now has `lhc_board_attach`. Attach the sketch PNG.
   - Place a "?" placeholder stamp on the track where it's needed.
   - If the request needs a 3D/visual asset, also queue it into `~/kauto-3d/queue` per `~/kauto-3d/QUEUE-CONTRACT.md` (kind/game set, status queued). Test this with a temp queue root only.
7. **Validation panel**, live:
   - lane overlap, minimum width, turn radius vs the ship's turning ability, reachable shards, lap-length and lap-time estimate
   - start/finish and checkpoints auto-placed, with manual override
8. **Version cards:** preview thumbnail, autopilot time, your best lap, problems, Playtest / Refine / Approve, and compare two versions side by side. Keep the existing playtest, refine and approve flows working.
9. **Draft format v2:** layers, stamps, width profile, skin, requests, notes.
   - Keep v1 drafts loadable.
   - Update the converter to emit everything the game supports today.
   - Store everything else as intent the refine agents and the owner can see.
